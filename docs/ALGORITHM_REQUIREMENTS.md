# 算法缺口与验收标准

## P0：主链路必须具备

| 算法 | 输入 | 输出 | 当前状态 | Demo 验收标准 |
| --- | --- | --- | --- | --- |
| 合规检测 | 文本、SKU、规则版本 | `passed/hits/suggestions` | 仅查询已有结果/空词库 | 关键规则召回率 ≥95%，单段文本 P95 <300ms |
| 直播话术生成 | SKU 参数、卖点、场次、模板、合规规则 | 分段脚本、关键词、时长 | TODO/固定文本 | 30s 内异步完成，结构化节点可直接展示，生成后再次合规检测 |
| 弹幕意图分类 | 弹幕文本、上下文 | `QA/WATER/COMPLAINT/PRICE/AFTER_SALES` + 置信度 | 固定 `GENERAL` | P95 <200ms；高价值问句召回率 ≥90% |
| RAG 问答 | 问题、SKU、知识库、场次上下文 | 回答、引用、置信度、是否需要人工 | 固定“AI生成的回答” | P95 <2s；无可靠知识时必须拒答/转人工 |
| ASR 脚本匹配 | ASR 片段、脚本节点 | 当前节点、匹配分、进度 | 前端手动模拟 | 最终片段后 500ms 内推进；短时误判不导致节点来回跳 |

## 推荐服务契约

算法服务统一采用异步提交：

```json
{
  "taskId": "alg-task-001",
  "type": "SCRIPT_GENERATION",
  "status": "RUNNING",
  "traceId": "trace-001",
  "inputVersion": "v1",
  "modelVersion": "model-20260714"
}
```

结果至少包含 `taskId/status/result/message/traceId/modelVersion/startedAt/finishedAt`。生产接入必须设置超时、重试、幂等键、熔断和人工降级；模型 Prompt、密钥和供应方 SDK 只放在 `infra-impl`。

## 第一版可选实现

- 合规：规则引擎为主，语义模型为补充。
- 话术：LLM + 商品知识 RAG + 输出 JSON Schema。
- 弹幕：轻量分类模型/LLM 分类 + 向量检索 + 受约束生成。
- ASR：直接接现有 ASR 服务，新增脚本节点相似度与状态机。
- 告警：先使用可解释规则，不必一开始训练预测模型。
- 复盘：确定性指标聚合 + LLM 摘要；指标计算不能交给 LLM。
